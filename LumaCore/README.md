# LumaCore

无外部依赖的纯 Swift 曝光、BGRA 区域亮度采样与空间加权库，供 iOS 17+ App 使用，也可在 macOS 13+ 独立测试。Swift tools 5.9；测试使用工具链内置 Swift Testing（Swift 6 / Xcode 16+）。

## 约定

- `ev100`：`log2(N²/t) − log2(ISO/100) + calibrationEV`。拒绝非正参数、NaN、无穷和非有限校准，返回 `nil`。
- `targetEV`：`EV100 + log2(胶片 ISO/100) − 补偿`。正补偿代表增加曝光。
- `deltaEV`：已校准测光基准减当前设置的 EV100，正值表示更亮。不要再次叠加校准或补偿。
- `solve`：M 保留原参数；A 仅调整快门；S 仅调整光圈；ISO 始终保留。按 EV 距离选择标准标称 1/3 档。没有自动胶片加曝偏置。
- `residualEV`：实际 delta 减请求补偿，表示相对目标的量化或限幅误差。正值表示比目标更亮。
- `isLimited`：自动参数的理想值超出支持范围时为真；正常取最近档的误差不算限幅。非法求解保留输入，返回 NaN 误差与 true，调用方应显示无效测光状态，不能当作曝光建议。
- 风险只是相对测光基准的经验阈值：负片/黑白负片 −2/+3 EV，反转片 −1/+1 EV；达到阈值即严重风险，绝对偏移小于 0.34 EV 为接近基准。它不测量场景高光/暗部，也不是胶片宽容度保证。
- `risk` 的调用方必须先确认 delta 有限；固定枚举没有无效读数状态，NaN 退回 balanced 不可用作有效读数。
- 档位为摄影常见标称数值，存在十进制四舍五入，因此最近档误差不严格等于理论 1/6 EV；测试以标称表最大间隔验证。
- `SpatialMetering.correction`：接收与可见画面裁切、方向一致的线性亮度网格，按矩阵/中央重点/点测权重返回 `log2(加权亮度/0.18)`，调用方只叠加一次到曝光基准。矩阵不包含厂商专有场景识别。
- `LuminanceSampler.grid`：从不透明 sRGB BGRA 缓冲区生成行优先、等面积矩形的线性亮度均值网格。App 使用 48×64 区域；每个可见像素按覆盖面积参与，非整除边界同样面积加权，裁切外像素和行填充字节不参与。通道线性化使用 256 项表，亮度为 `0.2126R + 0.7152G + 0.0722B`，alpha 不参与。
- `PixelCrop` 使用图像左上原点的整数像素范围。调用方负责让输入指针在同步调用期间有效；非法范围、过短缓冲区、溢出或网格比裁切像素更细均返回 `nil`。本库不复制整帧；App 仅在 capture 时调用，不放入每帧视频更新。
- `MeteringPoint` 使用左上原点的归一化坐标。点测圆直径为画面短边 16%，`clampedPoint` 保证圆区在边界内；`aspectRatio` 必须为画面宽/高。
- 空间加权拒绝非法尺寸、数量、亮度与宽高比；极暗亮度以 `1e-6` 防止无穷结果，这不保证真实暗部可测。

## 测试

在此目录运行：

```sh
xcrun swift test --disable-xctest --scratch-path ../.build/core
```

共 34 项测试。14 项覆盖 Sunny 16、ISO/快门/光圈方向、补偿、M 保留参数、A/S 联动、档位误差、双向限幅、非法输入、胶片风险阈值与 Codable 往返；12 项覆盖空间权重、点位明暗差异、边缘、横纵比、粗网格和输入验证。

另 8 项覆盖 BGRA 采样的均匀色与线性化、细纹、非整除区域、裁切、行跨度和非法输入。本轮 34 项全部通过，证据见[开发验证记录](../Docs/04-开发验证记录.md)。

本库测试不能证明 AVFoundation 测光准确性、胶片真实表现、相机预览、Photos 保存或真机性能。
