# LumaFrame：竞品体验对照与精简改进

日期：2026-10-30。目标是让测光、调参、保存更顺手，保持单页、原生和轻量。前两轮关注操作细节，第三轮按用户新要求加入大取景、镜头切换、空间测光和原生液态玻璃，第四轮继续收拢操作路径并完善采样；不以功能数量追赶竞品。

## 1. 对照范围与证据

参考 Lightme、Moegi《测光表－胶片摄影曝光助手》和 Light Meter Ultra。“测光表”存在多个同名产品，本次选择 Moegi 的产品作为明确对照对象。

证据来自开发者官网、App Store 描述及官方宣传截图；Lightme 和 Moegi 的截图已查看。未安装竞品逐步实测，不能据此确认点击次数、实际响应速度、测光准确度或当前版本的完整行为。下表的改进方向是针对光格的设计判断。

| 对照对象 | 公开资料可确认的特点 | 光格值得借鉴的细节 | 本轮取舍 |
|---|---|---|---|
| Lightme | 官网强调单手操作、主要控件在拇指范围、一键测光和同时展示多组等效参数；宣传图中补偿与 ISO 位于主界面下方 | 让现场常用调整直接可达，减少进设置寻找；测光与记录有清楚入口 | 保留底部主操作和原生滑杆，不复制多列刻度盘或长按、双击等隐含操作 |
| Moegi 测光表 | 官方图展示光圈与快门优先选择、底部参数和测光按钮、胶片入口 | 让用户看清哪个参数由自己决定、当前使用哪类胶片 | 保留可见模式选择，自动参数只读，胶片类型直接显示 |
| Light Meter Ultra | 官网描述锁定读数后交互调整参数，并提供不同档位间隔与设备范围设置 | 锁定状态应明确，调参后反馈应紧邻参数，下一步应自然 | 继续采用锁定后调参，先修顺主流程；本轮维持三分之一档，不增加设备配置页 |

Moegi 页面中有历史评论询问 EV 含义及模式入口。这些个案只能提醒我们注意可理解性，不能代表当前用户普遍遇到同样问题。因此，光格会区分“场景亮度 EV100”“当前参数的曝光偏移”和“目标补偿”，按需解释。

## 2. 第一轮六项改进

第一轮的以下六项已实现。当时 8 项 UI 用例经回归与定向复测，在两种 iPhone 模拟器均取得通过结果；这些结果不代替第二轮新增改动的回归。分批证据与未验项目见[开发验证记录](04-开发验证记录.md)。

| 当前摩擦 | 改进后的操作 | 验收重点 |
|---|---|---|
| 补偿藏在设置，恢复上次值后容易忘记 | 主界面显示当前补偿；点开原生面板调节，并可一键归零 | 非零状态可见；归零即时生效；M 模式仍需主动采用建议 |
| 点击自动参数后，编辑器全部变灰 | 自动项只读，不抢占编辑器；恢复 S 模式时选中可调快门 | A/S 始终有可调参数；不会暗中切换到 M |
| 保存后只有禁用按钮，旧读数还能换帧号再次记录 | 保存成功后主按钮变为“继续取景”；成功时清理旧读数，仍可分享当前记录 | 仅成功保存递增帧号；关闭页面后须重新测光才能新建记录 |
| EV 大卡片和重复说明抢占注意力 | 光圈、快门优先；偏移状态缩为简洁摘要，详细解释收进补偿面板 | 正常状态少干扰；越界和较大偏移仍清楚提示 |
| 胶片类型只在弹层中可见 | 顶部入口显示负片、反转片或黑白 | 视觉用户无需进入设置确认提醒依据 |
| 加减按钮朗读“一档”，实际步进三分之一档 | 朗读下一档目标值和真实步幅 | 光圈与快门方向不含糊；保留原生 Slider 和按钮语义 |

## 3. 第二轮流程检查

继续检查现有流程后，以下调整在第二轮完成。当时 12 项 UI 用例经回归与定向复测，在 iPhone 17 Pro 和 SE 两种模拟器均取得通过结果，设备目标无签名构建通过。这是历史批次，不能作为第三轮新增能力的验证结论；分批证据与真机边界见[开发验证记录](04-开发验证记录.md)。

| 检查发现 | 本轮调整 | 验收边界 |
|---|---|---|
| SE 常规字号下，偏移与补偿需要滚动 | 第二轮曾缩短取景以容纳首屏操作；第三轮已按用户偏好改为大取景优先 | 该首屏优先取舍已被新需求替换；首次授权和错误卡仍按内容撑高 |
| 记录参数烘焙在图片里，大字号与 VoiceOver 无法核对实际值 | 不可变草稿保留文字摘要，辅助标签读实际值；辅助字号显示可缩放文字 | 对照胶片、ISO、光圈、快门、偏移与测光时间 |
| 普通保存失败也引导去权限设置 | 区分授权拒绝与写入失败，保留草稿并显示“重试保存” | 模拟故障验证恢复路径，真实系统授权仍需单独验收 |
| 重测失败后旧快照仍可能被记录 | 新测光先清除旧读数，失败后记录保持不可用 | 重试成功后才可记录，不自动回退到旧场景 |
| 快速调参会留下已取消但仍在渲染的工作 | 同时只处理一个趋势渲染，待处理请求只保留最新值 | 不宣称已测得性能提升；真机功耗、延迟仍待验证 |
| 快速启停可能让旧相机回调覆盖新意图 | 按最终运行意图与会话版本过滤旧结果 | 已补代码防护，真机前后台与系统中断尚未验收 |

第二轮没有改变曝光公式、经验风险阈值或功能范围。记录图合成仍同步执行，不能描述为已完成的性能优化；第三轮空间亮度修正的计算变化另见技术契约。

## 4. 第三轮：大取景、空间测光与原生玻璃

这轮范围来自用户对更大取景、不同焦段、点/矩阵等测光方式及 iOS 原生液态玻璃的明确要求。此前“点测光延期”的边界已被该新需求替换；不是因为竞品拥有更多功能就全部增加。

| 用户意图 | 本轮实现与取舍 | 验收重点 |
|---|---|---|
| 看清取景，减少表单感 | 取景约占可用区域 61%，高度 300–500pt，辅助字号 300pt；SE 同样优先取景，参数可滚动，主操作固定 | 不再承诺补偿首屏可见；主按钮和关键参数仍须可达 |
| 快速切不同镜头/焦段 | 画面下缘显示实际可用镜头胶囊；硬件镜头切换真实相机输入，2×数码裁切明确命名 | 按硬件能力显示；iOS 26 标称焦距来自设备，旧系统只标估算相对倍率，不虚构 mm |
| 清楚选择测光区域 | 画面顶部独立测光 Menu：矩阵、中央重点、点测光 | 不与 A/M/S 曝光模式混淆；更换方式清旧读数 |
| 点选主体更直接 | 点测圆直径为画面短边 16%；点选移动圆心，位置菜单可选中心/上下左右 | 移动不自动测量；圆不越界；不强迫用户依赖坐标手势 |
| 更接近新 iOS 视觉 | iOS 26 悬浮控件使用系统 `glassEffect` 与玻璃按钮；正文、参数保留稳定底色 | iOS 17–25 和降低透明度有回退；不以透明效果牺牲可读性 |
| 状态可信，减少记忆负担 | 切镜头、测光方式或点位置即清旧基准；记录固定当次方式、镜头与点位置 | 保存后不会混入之后的取景设置；模式持久化、点位置新启动回中心 |

矩阵测光对可见裁切区域的 48×64 等面积网格等权汇总，中央重点使用中心高斯权重与外围底权，点测光读取圆形区域；结合同帧曝光元数据估计 EV。第四轮进一步将每格中心样点替换为区域线性亮度均值。它不等于厂商专有场景矩阵，也不提供真实高光剪裁或胶片成片预测。镜头切换、空间读数与灰卡精度必须分别在真机验证。

第三轮当时 26 项核心测试通过，15 项 UI 用例在两种 iPhone 模拟器上完整执行 30 次全部通过，设备目标无签名构建通过。这些是第四轮改动前的历史结果；测试与真实镜头、旧系统回退、完整辅助功能及性能的验证边界见[开发验证记录](04-开发验证记录.md)。

原生玻璃依据：[Apple 自定义视图 Liquid Glass 指南](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)与 [glassProminent 按钮样式](https://developer.apple.com/documentation/swiftui/primitivebuttonstyle/glassprominent)。

## 5. 第四轮：保持大取景，缩短操作路径

| 当前摩擦或边界 | 本轮调整 | 验收重点 |
|---|---|---|
| SE 能点参数值，但下方编辑器不在当前视野 | 主动点可调参数后最小滚动露出编辑器，默认取景大小不变 | 已可见时不强制拉齐；减少动态效果关闭滚动动画 |
| 非零补偿可能藏在参数下方 | 在取景 EV 下显示同一补偿面板的玻璃入口，归零后收起 | 状态可见，不新增另一套补偿设置 |
| 锁定点测后位置菜单不完整 | 始终可达的测光 Menu 提供中心/上下左右 | 不必先返回取景；选择清旧读数且不自动测量 |
| 长记录预览需要滚到末尾才能保存 | 保存/重试/继续与分享固定底部；风险可定位，失败定位错误，成功提示固定 | “查看曝光提醒”不自动确认；未确认仍禁止导出，正文不被固定栏遮挡 |
| 中断尚未解除时可能尝试恢复相机 | 启动前后及恢复/切镜/采样核验系统 `isInterrupted` | 只补状态防护，实际中断恢复仍待真机 |
| 每格仅取一个样点可能漏掉细纹亮暗 | BGRA 可见区域按 48×64 等面积分区求线性均值，边界按覆盖面积加权 | 每个可见像素参与；只在 capture 时计算，不增加每帧常驻运算 |

亮度线性化采用 256 项查找表，但本轮没有测得硬件耗时、功耗或精度提升。记录图合成仍同步执行；固定按钮也不代表合成已转为后台。

本轮共 34 项核心测试通过，18 项 UI 用例在两种 iPhone 模拟器上执行 36 次全部通过，设备目标无签名构建通过；44 张实际模拟器截图已更新。具体证据及硬件验证边界见[开发验证记录](04-开发验证记录.md)。

## 6. 精简与轻量边界

沿用 SwiftUI 系统控件、语义颜色和 SF Symbols，保持单页工作流与渐进展开的说明。继续无账号、无后端、无第三方运行时依赖，本轮不新增常驻测量任务。轻量也包括减少用户记忆的状态和操作规则；源码 ZIP 大小不能与竞品 App Store 安装体积直接比较。

点测光已进入第三轮范围；多点读数合并、胶片数据库、ND 管理、历史库和云同步仍不提供。竞品拥有某项能力，不等于光格当前需要它。镜头与测光入口保持在同一取景页，不增加新的一级页面。

后续先观察真实用户完成“首次测光、调整一档、归零补偿、保存后继续”四项任务，记录完成率、误触与求助点，再决定是否追加改动。真机测光精度和相机生命周期另行验证，不能由界面顺手或模拟器通过推定。
